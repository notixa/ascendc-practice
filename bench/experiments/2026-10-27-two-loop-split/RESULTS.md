# 实验 1 — 把 causal mask 移出前缀循环（❌ 失败，已回退）

## 假设

循环体内有 8 步向量依赖链 → 8 个 `BAR`。causal 下只有最后 1 个 KV 块需要 mask，
把 mask 移动到一个独立的「对角段」，前缀循环只剩 7 个 `BAR`：

```
(31×7 + 8) / (32×8) = 0.879   → 预期 −12%
```

## 改动（已回退）

单循环 → **两段循环**：

```python
for j in range(T_k - 1 if IS_CAUSAL else T_k):   # 前缀，无 mask
    ...
if IS_CAUSAL:                                     # 对角，1 次，带 mask
    ...
```

（`if IS_CAUSAL` 是 constexpr，full 模式整段被 DCE，不会退化。）

## 测量

`bench/bench_fa.py --only triton --mode both`，warmup=10 / iters=50 / repeats=5，取中位数。

## 结果

| case | 改前 (ms) | 改后 (ms) | 变化 |
|---|---|---|---|
| **causal N=4096** | 1.550 | **1.767** | **+14.0%** ❌ |
| **causal N=2048** | 0.456 | **0.504** | **+10.5%** ❌ |
| **causal B4 N=2048** | 1.626 | **1.875** | **+15.3%** ❌ |
| causal N=1024 | 0.486 | 0.447 | −8%（但该点受 launcher 开销支配，不可信） |
| full N=4096 | 2.860 | 2.894 | +1.2%（噪声）|
| full N=2048 | 0.744 | 0.752 | +1.1%（噪声）|
| `max_err` | ~1.0e-3 | ~1.0e-3 | 不变 ✓ |

**causal/full 比值从 0.542 恶化到 0.611。**

## 结论

**推翻假设，回退。**

去掉的那条 mask `BAR` 并没有带来收益，反而因为结构性改动付了更大的代价。
可能的原因（未验证，按可能性排序）：

1. **代码体积翻倍 → icache 压力**。`T_k` 小的 task（`i=0` 时 `T_k-1=0`）只跑尾段，
   前缀循环的代码纯属占空间。
2. **尾段是独立基本块**，编译器无法跨迭代做软件流水，直行代码的调度更差。
3. mask 那条 `BAR` 本来就和相邻算子合并了（KB 卡对同类改动的结论是「噪声内」）。

### 与 KB 卡的对应

`flash_attention_optimization.md` §3.2 已把「运行时 `scf.if` 只在对角/边界块做掩码」
实测为**噪声内**。我们用了更强的形式（真两段循环，编译期分支），结果是**负收益**。

**⇒ 「减少循环体内的 BAR 数」这条路，必须靠减少*数据依赖*，而不是靠*搬移语句*。**

## 保留了的两处（与本实验无关的顺带修复）

| 改动 | 原因 |
|---|---|
| `bq = min(bq, bk)` in `base_tile` | 保证 `BQ ≤ BK`，让「只有最后一块需 mask」成为设计保证 |
| mask 加 `+ delta_qk` | 与 `T_k` 的全局坐标一致，为 chunk prefill 铺路 |
